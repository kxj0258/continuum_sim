# MuJoCo–PCC Diagnostics Design

**Goal:** Add observation-only diagnostics to every artifact-enabled MuJoCo scenario so a manual rerun can distinguish PCC geometry mismatch, analytic Jacobian error, and actuator/command-response lag.

## Confirmed scope

- No YAML switch: diagnostics are generated by default for every enabled arm when `backend.type` is `mujoco` and artifacts are enabled.
- Viewer-only scenarios with `artifacts.enabled: false` remain unchanged.
- Compute diagnostics after the run in the artifact layer, not in task-specific controllers.
- Preserve full PCC bending/tendon Jacobians plus derived position, velocity, singularity, and residual arrays.
- Generate per-arm position, velocity/response, and Jacobian-conditioning plots.
- Add final/mean/max summaries to artifact metadata.
- A diagnostic failure must not discard the existing run artifacts.

## Residual separation

1. Compare PCC FK and MuJoCo positions in the arm mount frame to remove mobile-base motion.
2. Compare the analytic PCC Jacobian prediction with PCC FK finite differences to isolate Jacobian/local-linearization behavior.
3. Compare PCC FK finite differences with MuJoCo finite differences to isolate model mismatch under the same measured tendon displacement.
4. Compare command-based prediction with MuJoCo motion while recording the base contribution separately to expose actuator and tendon-target lag.

## Non-goals

- Do not change control gains, solver behavior, tendon target integration, scenario configuration, or viewer behavior.
- Do not provide real-time plotting in this change.
- Do not run tests, validation, formatting, builds, installation, viewers, demos, or simulations automatically.
