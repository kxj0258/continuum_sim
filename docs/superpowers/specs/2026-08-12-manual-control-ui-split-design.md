# 手动控制入口与界面拆分设计

## 目标

降低手动控制期间 Matplotlib 窗口创建、控件同步和图表重绘对交互响应的影响，并让曲率控制与原始拉线调试具有清晰、互斥的操作入口。

本次改造范围仅限手动控制工具。自动场景控制、观察臂相机反馈算法和视频录制管线不受影响。

## 启动入口

删除 `scripts/run_manual_control.py`，不提供兼容入口，新增两个独立程序：

- `scripts/run_manual_curvature_control.py`：曲率控制入口。
- `scripts/run_manual_tendon_control.py`：原始拉线调试入口。

两个入口都接收场景路径、控制面板刷新率、状态窗口刷新率和 MuJoCo 三维窗口刷新率等适用参数。只有拉线监测功能通过 `--show-tendon-monitor` 显式开启，默认关闭。手动控制入口不再接收相机刷新率或曲率步长参数。

## 总体架构

两个程序共享一个无界面的手动控制会话。会话拥有仿真后端、`50 Hz` 控制工作线程、目标快照、最新状态快照、基座目标、运行状态和错误状态。它不创建 Matplotlib 图形，也不直接触发图形界面重绘。

图形界面由若干职责单一的窗口组成：

1. 曲率控制窗口只创建每段 `kx/ky` 滑块、数值输入框、基座控制和通用运行控件，曲率范围固定为 `-30～+30 1/m`。
2. 拉线控制窗口只创建每根拉线的滑块/数值输入框、拉线预设、基座控制和通用运行控件。
3. 实时状态窗口只显示文本诊断信息，默认创建并低频刷新。
4. 拉线监测窗口只显示拉线长度和拉力柱状图，仅在命令行显式要求时创建。
5. MuJoCo 被动三维窗口继续独立显示机械臂仿真模型。

控制模式由启动入口固定：曲率程序使用 `bending_compatible`，拉线程序使用 `raw_tendon_debug`。界面中不再提供运行时模式切换，避免创建另一种模式的控件，也避免目标在模式切换时产生隐式投影。

## 控制窗口

两个控制窗口都保留以下整机调试能力：

- 移动基座六自由度目标调整及步长切换。
- `Reset`、`Zero arms`、`Zero base`、`Step` 和 `Run/Pause`。
- 当前模式适用的命名预设。

曲率滑块和数值输入框回调只更新会话中的绝对曲率目标并发布待刷新信息。拉线滑块/数值输入框回调同样只写目标快照。控件值回写集中在控制窗口自己的低频刷新阶段，且只同步发生变化的机械臂和曲率分量；批量同步期间关闭控件绘制和事件，最后只请求一次窗口重绘。

关闭主控制窗口将停止控制线程并关闭该程序创建的状态窗口、可选拉线监测窗口和 MuJoCo 三维窗口。单独关闭只读状态窗口或拉线监测窗口不会中止仿真控制，窗口关闭后也不会被自动重建。

## 状态与拉线监测窗口

实时状态窗口不包含拉线长度图或拉线拉力图，仅保留原有诊断文本，包括：

- 仿真时间和固定控制模式。
- 基座目标/实际位置与姿态。
- 各臂各段目标/实际曲率和世界坐标位置。
- 可用时显示末端力/力矩及饱和状态。

拉线监测窗口复用持久化柱状图实现。柱状图只创建一次，后续更新 bar 高度和必要的坐标范围，不清空坐标轴，不重建图例或刻度。该窗口默认不创建，因此常规手动控制不承担柱状图计算和重绘开销。

## 相机与三维显示

手动控制应用移除观察臂相机相关的附件查询、离屏渲染工作线程、帧邮箱、Matplotlib 图像 presenter 和相机调度门。手动控制不会创建视觉反馈图像窗口，也不会执行相机帧渲染。

场景中的相机几何和传感器配置可以保留，因为其他自动任务仍可能使用它们；本次只断开手动控制运行路径。

MuJoCo 三维窗口继续使用私有 `MjData` 快照和基于时间的刷新门。复制动态状态时短暂持有仿真锁，`mj_forward` 和三维窗口同步在锁外执行。

## 数据流与线程边界

1. 图形界面回调修改会话目标，记录输入时刻并发布最新版目标快照。
2. 50 Hz 控制线程从最新版目标快照计算肌腱速率和基座速度，在仿真锁内推进 MuJoCo，并发布最新版系统状态。
3. 图形界面主线程的控制窗口定时器只同步待刷新控件并请求一次控制窗口重绘。
4. 状态窗口、可选拉线监测窗口和 MuJoCo 三维窗口分别通过基于单调时间的刷新门消费同一个最新状态快照。
5. 慢窗口只会丢弃中间显示帧，不积压状态，不阻塞控制线程。

所有 Matplotlib 绘图对象的创建和更新仍在图形界面主线程完成。控制工作线程不接触 Matplotlib，避免图形界面后端的线程安全问题。仿真状态和控制目标通过锁与最新值邮箱传递。

## 错误处理

- 控制工作线程异常记录在会话中，由主控制窗口在下一次刷新时输出堆栈、切回停止状态并恢复 `Run` 标签。
- 越界曲率输入限制到 `-30～+30 1/m`；非法曲率和拉线文本输入恢复为最近有效值，不写入无效目标。
- 若 MuJoCo 三维窗口被用户关闭，控制与其他窗口继续运行；若主控制窗口关闭，则执行统一清理。
- 可选窗口更新时先检查窗口是否仍存在，避免对已关闭 Figure 调用绘制。

## 测试与验收

自动测试应覆盖：

- 两个脚本分别调用正确的固定控制模式，旧入口已删除。
- 手动控制窗口管理器不再创建或调度相机工作线程和图像窗口。
- 曲率窗口只创建曲率滑块/数值输入框，拉线窗口不创建曲率控件。
- 状态窗口只更新文本，不创建长度或拉力柱状图。
- 拉线监测窗口默认关闭，仅在显式参数下创建并复用柱状图绘图对象。
- 控制线程继续独立于所有 Matplotlib 定时器运行，目标与状态传递不积压。
- 窗口关闭顺序和控制线程异常能够正确清理资源。

手动验收分别启动两个新入口，确认相机窗口从未出现；检查曲率和拉线控制即时响应、状态文本低频更新、可选拉线图默认关闭且显式开启时独立显示；同时观察终端时序统计，确认控制周期不随窗口刷新频率变化。
